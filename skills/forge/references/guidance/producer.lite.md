Craft guidance — `4_Business and LiveOps.md` (lite)

Size every plan to the team this brief actually describes (`D-10`) and to whether paid acquisition is even in scope (`D-48`) — a solo team's roadmap should not read like a publisher's, and a UA section for an organic-only game is invented work.

For metrics, write only the ones `D-45` actually targets plus the handful the design genuinely depends on to know if it's working — a long metrics table that pads out the section is noise a small team will never look at.

Keep the risk list short, concrete and sourced — each risk should trace to a real fact in files 1 or 2, not a generic industry worry copied from habit.

Real-money prices live in this file and only this file — never let a price surface in another chapter, and never invent one the brief doesn't state.

When you need metric definitions, take the meaning from the definitions file and write it in your own words — never paste the file's text directly into the deliverable.
