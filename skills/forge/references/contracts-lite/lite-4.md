# Contract — 4_Business and LiveOps.md (lite profile)

**Conventions**: `brief:D-xx` = a decision field from `brief-schema.md` · `lite-N` = one of this profile's other four output files · `tmpl` = `${CLAUDE_SKILL_DIR}/templates/lite/4-business-liveops.md` skeleton (headings fixed, guidance comments removed in output) · `check` = `${CLAUDE_SKILL_DIR}/checklists/lite/lite-4-business.md` · `data` = `${CLAUDE_SKILL_DIR}/data/<file>`, the only allowed source of external facts. Output language = `brief:D-12`; headings keep the English `4.` prefix in every language. A "N/A section" is still written: heading, one paragraph stating why it is minimal and which decision caused it.

- **Owner / model**: `gdd-producer` / **sonnet** — same agent and discipline as the full profile's `12_Management.md`, rewritten for casual/ads-driven reality rather than a multi-year roadmap.
- **Consumes**: `1_Concept.md` §1.5 (feature set), §1.7 (audience/platforms/business model); `2_Core Gameplay.md` §2.1 (core loop), §2.3 (mechanics catalogue), §2.4 (economy), §2.6 (stage structure), §2.9 (feature list); `brief:D-06, D-09, D-24, D-30, D-31, D-36, D-38, D-40, D-44, D-45, D-46`. Dispatched in W3 alongside UX and Tech, reading only files 1 and 2. Per `profile-casual.md` § Wave table, delivered as `WORK/inputs/_anchor.md` plus script-sliced excerpts of §1.5/§1.7 and §2.1/§2.3/§2.4/§2.6/§2.9.
- **tmpl**: `templates/lite/4-business-liveops.md` · **check**: `checklists/lite/lite-4-business.md` · **data**: the `data/monetization/` slices `D-06` selects (see `data/monetization/_index.md`); `data/casual/metrics-definitions.md` (see `data/casual/_index.md` for the selector rule)
- **Sections**:
  - §4.1 Business Model Summary — one paragraph restating `D-06` and how it maps to the mechanisms detailed below; no re-derivation of audience/platform (already in `1_Concept.md` §1.7).
  - §4.2 Ad Placement Design — where rewarded video appears, tied explicitly to a moment in §2.1/§2.6 (e.g. "offered after a failed stage attempt, before a retry"); interstitial cadence stated as a named tunable ("every N stage completions (tunable)"), never a fixed invented number; banner policy (placement, or explicitly "no banners"). Name the mediation platform/network from `D-46` if resolved; if `D-46 = UNDECIDED`, describe placement logic network-agnostically and list `D-46` in Open Decisions.
  - §4.3 IAP & Remove-Ads — remove-ads price tier and any consumable IAP, using only mechanisms listed in `D-30` (identical hard rule to the full profile's §12.6/§4.7) — never inventing a mechanism `D-30` doesn't list.
  - §4.4 KPI Definitions & Targets — pull every metric definition verbatim in meaning (not necessarily wording) from `data/casual/metrics-definitions.md`; never restate a definition differently in two files. Target values come only from `D-45`; if `D-45 = UNDECIDED`, every metric is defined with no target column filled, and `D-45` is listed in Open Decisions — do not fabricate a plausible-sounding CPI or retention figure. Any target that is present is tagged `(target)` and cites `D-45` as its source.
  - §4.5 Creative & Playable Ad Concept — a short concept for the ad creative/playable that will run the CPI test in §4.6: which mechanic from §2.3 it demonstrates, what the hook is in the first 5 seconds, what the CTA moment is. Elaboration, not a decision — grounded in §2.1/§2.3, never inventing a mechanic that isn't in `2_Core Gameplay.md`.
  - §4.6 Roadmap — phases: prototype → CPI test → soft launch → global launch. Each phase: goal, exit criteria (a testable condition, e.g. "CPI test: ≥3 creative variants run, cost-per-install and D1 measured against `D-45` if resolved, else measured as a baseline to set `D-45` retroactively"). Durations stay relative ("T+n") unless `D-10`/team info is available in the brief; do not invent calendar dates.
  - §4.7 Risk Register — casual-specific risks (ad-fill dependency, CPI volatility, platform policy changes on ad SDKs) plus anything the reviewer or the agent itself can trace to an earlier lite file; every row needs a source and an owner, same discipline as the full profile's §12.5.
  - §4.8 LiveOps Plan — CONDITIONAL: only if `D-24 ≠ None`. Cadence from `D-36`, content types scoped to `D-09`/`D-23` (e.g. weekly stage-pack drops for a level-select structure). Otherwise the single line: "No live operations planned post-launch (D-24)."
  - §4.9 Localisation & Compliance — launch languages (`D-38`) and rating/compliance path (`D-40`), condensed from the full profile's §12.9.
  - Open Decisions — one bullet per `UNDECIDED` brief field and GAP. `D-45`/`D-46` = `UNDECIDED` always appear here per the Depth rule when they leave §4.2/§4.4 without a target or network.
- **Depth rule**: `D-06 = Premium` (unusual for this profile's preset, but possible on an edited preset) → §4.2/§4.3 collapse to one paragraph noting there is no ad/IAP plan and stating the pricing tier as an Open Decision, mirroring the full profile's §12.6 Depth rule. `D-24 = None` → §4.8 one line. `D-45 = UNDECIDED` → §4.4 definitions-only, no target column.
- **Hard rules**: every ad/IAP mechanism named uses only `D-30`; every KPI is **defined, never given an invented target** — a target value with no `D-45` source is a fabrication, identical in spirit to the full profile's Consistency rule 8. No currency or market-size figures beyond what the brief states.
