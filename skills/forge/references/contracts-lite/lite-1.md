# Contract — 1_Concept.md (lite profile)

**Conventions**: `brief:D-xx` = a decision field from `brief-schema.md` · `lite-N` = one of this profile's other four output files · `tmpl` = `${CLAUDE_SKILL_DIR}/templates/lite/1-concept.md` skeleton (headings fixed, guidance comments removed in output) · `check` = `${CLAUDE_SKILL_DIR}/checklists/lite/lite-1-concept.md` · `data` = `${CLAUDE_SKILL_DIR}/data/<file>` reference knowledge, the only allowed source of external facts. Output language = `brief:D-12`; headings keep the English `1.` prefix in every language (e.g. `# 1. Concept` even in Vietnamese body text). A "N/A section" is still written: heading, one paragraph stating why it is minimal and which decision caused it.

- **Owner / model**: `gdd-concept-architect` / **opus** — same agent and discipline as the full profile's `3_Game Overview.md`; this contract is a compressed re-scoping of that one, not a new role.
- **Consumes**: `WORK/brief.md` (all of Section A and B; `D-43`, `D-44`). This is the only lite file with no upstream lite file to read — it is the anchor, dispatched first (W1), exactly like `3_Game Overview.md` in the full profile.
- **tmpl**: `templates/lite/1-concept.md` · **check**: `checklists/lite/lite-1-concept.md` · **data**: `data/game-design-patterns.md`
- **Sections**:
  - §1.1 Document Header — game name (`D-01`/final `game_name`), GDD version (`D-15`), profile (`hyper-casual`/`casual`), date, rights holder (`D-41`, or `[RIGHTS HOLDER — UNDECIDED]`), language (`D-12`), platforms (`D-04`). One-line copyright notice ("© <year> <D-41>. All rights reserved.") and one-line confidentiality statement. This section replaces the full profile's `1_Copyright Information.md` and `2_Version History.md` — condensed to a header block, not two chapters. Seed a single-row version table (version · date · summary) the same shape as the full profile's §2.1, for future runs to append to.
  - §1.2 Name Candidates — CONDITIONAL: only if `D-01 = GENERATE` or `UNDECIDED`. Propose exactly 3 candidate names inline (not the full 8-candidate `gdd-namer` dispatch the full profile runs in its own wave) — each with a one-line rationale tying it to the pitch/tone, and the same "cannot verify trademark/app-store availability" caveat `gdd-namer` carries. Otherwise write the single line: "Not applicable — working title already set (D-01)."
  - §1.3 Game Concept — `D-02` quoted verbatim as the one-liner, then a 3–5 sentence expansion (player role, core-loop hint, primary challenge). Shorter than the full profile's §3.1 expansion — casual pitches rarely need 5–7 sentences of world-building.
  - §1.4 Design Pillars — 3–5 pillars, each named + one sentence of meaning + one sentence of what it forbids. Same hard rule as the full profile: derivable only from `D-02`/`D-08`/`D-43`.
  - §1.5 Feature Set — top 6–10 features (fewer than the full profile's 8–12, matching casual scope), each tagged P0/P1/P2 and mapped to a pillar from §1.4. `D-43` items are P0; `D-44` items listed under "Explicitly out," never as features.
  - §1.6 Genre & Comparables — `D-03` + `D-13`, each comparable with one thing to borrow and one to avoid. If `D-13 = none`, say so plainly.
  - §1.7 Target Audience & Platforms — one paragraph merging `D-05` (audience/motivations) with `D-04` (platform list) and a one-paragraph business-model summary (`D-06`) — mechanism detail lives in `4_Business and LiveOps.md` §4.2–§4.3, not here.
  - §1.8 Setting & Theme — the thin narrative substitute for the full profile's `5_Story, Setting and Character.md`: tone/mood from `D-08`, and however much framing `D-21` calls for (`None` → one line stating there is no narrative framing; `Light framing` → a short paragraph: setting flavour, one line on the player-character if any; casual profiles should rarely see `D-21` above `Light framing` — if they do, treat it as an escalation signal per `profile-casual.md` § When not to use this profile, and say so in Open Decisions).
  - §1.9 Scope & Glossary Seed — `D-09` scope statement (session length target) plus a project-scope estimate line (levels/stages, characters if any — every number `(est.)`), followed by 8–15 glossary terms (fewer than the full profile's 10–20) this GDD will use consistently. Every later lite file must reuse these terms verbatim (this is Lite Consistency rule 1 — see `profile-casual.md`).
  - Open Decisions — one bullet per `UNDECIDED` brief field touched and per GAP placeholder, same format as the full profile (`- D-xx <field> — UNDECIDED — affects §N.x` / `- G-n — <what is needed> — §N.x`).
- **Depth rule**: fixed except §1.2 (conditional on `D-01`) and §1.8 (scales with `D-21`, per above). This file, like its full-profile counterpart, is always written in full otherwise — it is the anchor every other lite file reads.
- **Hard rules**: pillars must be derivable from `D-02`/`D-08`/`D-43`; never introduce a business model, platform, or audience absent from the brief. Name candidates in §1.2 are elaboration bounded by the same anti-fabrication discipline `gdd-namer` follows (never claim trademark clearance). No agent proposes a `D-01` value it invents outside these 3 candidates without flagging it as such.
