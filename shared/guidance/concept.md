# Guidance — concept.md

- A pillar is a sentence with teeth: name, meaning, and what it forbids. Test: could a reasonable studio ship the opposite? If not, the pillar does no work.
- Write pillars after you know the must-haves (D-43) and exclusions (D-44). A pillar whose Forbids blocks a must-have is a defect in the pillar: reword it before moving on.
- 3–5 pillars. More and nothing is a priority; fewer and two ideas are probably merged.
- Core Loop is a verb cycle the player performs ("aim → shoot → collect → upgrade"), never a feature list.
- Session length and run length are different numbers: a mobile session can hold several runs. Keep them apart.
- Systems list: one row per system a team would build and own. Do not split one system into many rows to look thorough; do not merge unrelated ones to look small.
- Tier `core` is only what the core loop cannot run without. Everything else is `later`, even if it is important for launch.
- Glossary terms are binding on every document: settle spelling and capitalisation deliberately. Seed only terms that recur (currencies, core verbs, named modes), not one-off nouns.
- References: one thing to take and one to avoid per game. A reference with nothing to avoid is fan praise.
- Experience: say what the art and tone are *for* (readability, mood the player should feel), not only how they look.
- Re-read the draft once and cut every sentence that is not a decision, a pillar, a loop step, a system or a defined term.
