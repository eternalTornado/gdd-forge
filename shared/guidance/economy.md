# Guidance — economy systems

Currencies, sources and sinks, monetization mechanisms, store.

- One table of sources and sinks per currency. A currency with sources and no sinks inflates; sinks with no sources stall the player.
- Monetized sinks use only mechanisms in D-30 and respect every limit in D-31, including mechanisms mentioned in passing.
- Real-money prices are a decision: if the user has not given them, propose price tiers as a decisions.md row and list the question under Open Questions. Never invent a store price silently.
- For ad-based models, state placement rules (when a rewarded video is offered, interstitial cadence, what the player gets) as rules with tunables, not as mood.
- KPI names (D1, ARPDAU…) only if the design depends on them, and only as definitions; never invent target values the user did not give.
- No market sizes, eCPM or conversion benchmarks unless a data file you were given states them.
- Premium games: no IAP economy. Describe the in-game currency loop only, if there is one.
- Size the economy to the team and scope: a solo hyper-casual game does not need three currencies.
