# Review checklist — systems/<slug>.md

Judgement items only; `gdd_check.py` already checks headings, budgets, tunable ownership, references and glossary spelling.

1. **Concept fit:** Purpose names a pillar; no rule does what a pillar forbids or what D-44 excludes.
2. **Decisions:** nothing contradicts `decisions.md`; any choice that changes other systems is a `decisions.md` row, not a silent pick.
3. **Monetization:** only D-30 mechanisms, every one within D-31 limits.
4. **Testable rules:** each rule can be implemented and checked from its wording alone; no adjectives standing in for rules.
5. **Closure:** every item, screen, currency, state or system the doc mentions is defined in this doc or in the doc a `→` reference points to.
6. **Edge cases:** the obvious edges (empty, max, interrupted, offline, simultaneous) are covered where they apply.
7. **Observable behaviors:** each "When…, …" line is something a player sees or does in play, and together they cover the main rules.
8. **Consistency with other systems:** no value or rule contradicts a system doc this one references or is referenced by.
9. **Proportion:** depth matches D-09 scope and the system's tier; no section sized for a bigger game.
10. **Open Questions:** only things that cannot be proposed (conflicting sources, real-money prices, legal commitments), each with a recommended answer.
